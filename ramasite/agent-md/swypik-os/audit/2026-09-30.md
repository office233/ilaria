# SwypikOS audit — 2026-09-30

## Scope and coverage

The working tree already contained substantial modified and untracked Go/native
kernel work before this audit. Those changes were preserved. This report describes
the additional audit work, not ownership of every difference from Git HEAD.

The final safe inventory identified 363 source/document/build text files,
including about 200 Go files. Filenames were inventoried across the product,
including the formerly hidden product-local workflow definitions. Review focused
on the Windows entrypoint/controller, agent approval and filesystem boundaries,
checkpoint adapters, search persistence/crawl/local indexing, durable Control
Kernel, installer truthfulness, driver verification and native capability/IPC
contracts. Prototype numeric-control modules were also inspected. The entire Go
product was tested and vetted; the native host gate compiled and ran its full C
and assembly source list.

The accompanying `2026-09-30-source-inventory.csv` records every safely selected
text file's path, size, line count and category. It excludes private/data/ignored
paths and binaries. Inventory membership does not claim manual line-by-line review.

This is an inventory plus critical-path review and executable validation, not a
claim that every line, firmware path or physical device was manually audited.
Private files, tokens, user data, ignored model weights and pre-existing generated
binaries were not read as source material. The tests used isolated temporary state;
no disk installer, real actuator, privileged kernel operation, firmware update,
model training, push or external publication was performed.

## Corrections

| Area | Defect and resulting behavior | Evidence |
| --- | --- | --- |
| Search batch capacity | Repeated URLs counted as multiple new documents and incorrectly exceeded capacity. One URL now occupies one slot; its last occurrence wins. | `core/search/audit_regression_test.go` |
| Caller ownership | Resource clipping modified the caller's input slice. The engine now owns a copy before truncation. | Same regression suite |
| Search consistency | Reusing a supplied digest hid changed text. No-op detection also compares the actual stored text. | Same regression suite |
| Search lifecycle | Writes/deletes after `Close` silently changed RAM with no persistence. Mutations now reject a closed index. | Same regression suite |
| Search replay | A line containing multiple JSON values was partially accepted. Replay requires exactly one object and quarantines ambiguous data. | Same regression suite |
| Physics prototypes | NaN/infinite vehicle or robot data could produce `Safe=true`, sometimes with invalid JSON. Invalid/domain/overflow inputs now produce a finite veto. Reverse robot speed no longer reduces the modeled load. | Three tests in `core/worldmodel/audit_regression_test.go` |
| CBF prototype | Non-finite nominal control could claim a solved projection; negative velocity produced unbounded holding torque. Invalid numeric input now enters a finite holding path, and holding torque is bounded in either direction. | Two tests in `core/cbf/audit_regression_test.go` |
| Linux checkpoint fixtures | Private-directory tests assumed `t.TempDir` was mode 0700; corruption tests predated the quarantine behavior. Private fixtures explicitly set 0700. Tests still reject public directories, symlinks, hardlinks, FIFOs and public checkpoint files; corruption is rejected, preserved and never executed. Runtime protection was not weakened. | `core/agent/store_linux_test.go` |
| Native host portability | COFF-only assembly directives and sections failed ELF builds. Metadata now selects COFF/ELF correctly, ELF assembly marks the stack non-executable, and Linux host tests disable PIE for absolute stub tables. The explicit Microsoft x64 ABI stays intact. | Windows Zig, Linux Zig/musl and Linux GCC host test execution |

All ten newly added Go regression tests failed on their original implementations
and passed after the corrections. Existing Linux checkpoint assertions were
updated to verify the intended current behavior, rather than skipping protection.

Nineteen existing Go files were formatted with `gofmt` after backups. Module tidy
corrected `x/net` and `x/text` to direct dependencies without changing versions or
checksums. Original files were backed up outside the checkout in a dedicated
temporary audit directory before editing.

The README and Windows design document now match the current seven-tab desktop,
Windows approvals/recovery, JSONL index quarantine and next-restart workspace
selection. Native-kernel documentation no longer assumes a stale workstation
tool inventory. Comments no longer claim that the CBF/physics prototypes have
physical certification or guaranteed latency. The two inactive product-local CI
workflows were preserved in `docs/ci-archive`; active verification belongs to the
Nexus root workflow.

## Highest-value next work

1. **Confinement and identity:** implement explicit file/network capabilities for
   approved child processes and a real Windows sandbox; add OS credential storage
   and a documented threat model. Approval and Job Object cleanup currently
   provide consent/lifecycle control, not filesystem or network confinement.
2. **Executable integration evidence:** add root CI jobs for native PE packaging
   and diskless BIOS/UEFI boot, then a disposable-workspace desktop/model journey
   covering approval, cancellation, checkpoint restart and uncertain outcomes.
   Preserve the distinction between compile, boot, model inference and hardware.
3. **Native-kernel maturity:** exercise MMU/interrupt/DMA revocation under faults,
   then scheduler isolation, multiprocessor concurrency, signed driver admission,
   recovery and supported-device matrices. Host fixtures validate contracts; they
   do not establish firmware or physical hardware parity.
4. **Preserve product ownership:** keep model/runtime/training in Ilaria. Retire or
   adapt historical OS training prototypes through the stable Ilaria protocol;
   do not grow a second training implementation. Swyp owns plan semantics and
   contracts; the OS owns admission, capabilities and effect execution.
5. **Durable search:** add exclusive-writer protection, bounded compaction/replay
   and injected write/fsync/crash tests. Audit incomplete local-directory walks
   before stale-entry removal and replace repeated robots-rule compilation with
   bounded precompiled policies. Preserve the original data on every repair path.
6. **Reliable desktop:** move endpoint changes entirely off the UI thread, specify
   conversation-reset behavior during inference, and add accessibility, keyboard
   navigation and measured Unicode/font coverage.
7. **Measurable quality:** publish reproducible latency, memory, search relevance,
   task-success and recovery benchmarks with fixed datasets and explicit hardware.
   Isolate prototype finance/BCI/physical-control claims until independently
   calibrated and validated. A competitive claim needs measured comparisons,
   not simulation names or passing unit tests alone.
