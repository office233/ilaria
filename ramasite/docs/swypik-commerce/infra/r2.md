# Media pe Cloudflare R2 + CDN

Decizia ownerului (2026-09): toată media (video, audio, imagini) stă în **Cloudflare R2** și se
servește de pe **CDN-ul Cloudflare pe un domeniu custom** (ex. `media.swypik.com`). Serverul
aplicației (VM Azure, egress ~0,09 $/GB) **nu vede niciun byte de media**:

| Flux | Cine mută bytes-ii | Prin app trece doar |
|---|---|---|
| Upload video / audio (multipart) | browser → R2 (URL-uri presemnate pe endpointul S3) | semnarea URL-urilor |
| Redare publică (feed, episoade gratuite, piese free, imagini) | R2 → CDN → browser | URL-ul |
| Redare privată/plătită (episoade, piese premium) | R2 → Worker pe CDN → browser | URL-ul semnat (token criptat) |
| Imagini `next/image` | CDN → browser (opțional Cloudflare Image Transformations) | nimic (`/_next/image` nu mai e folosit) |
| Transcodare | video-worker ↔ R2 | nimic |

Excepție cunoscută (mică): imaginile urcate prin formular (avatar ≤5 MB, poze produs, dovezi retur)
trec prin app pentru validare/redimensionare cu `sharp`, în memorie; vezi „Rămas de făcut”.

Local rămâne **MinIO** (`docker-compose.social.yml`), același cod: `lib/storage/*` vorbește cu orice
backend S3-compatibil.

## Variabile de mediu

| Variabilă | Unde | Exemplu prod | Rol |
|---|---|---|---|
| `S3_ENDPOINT` | app, worker, Go | `https://<account-id>.r2.cloudflarestorage.com` | endpointul S3 folosit de server |
| `S3_REGION` | app, worker, Go | `auto` | R2 cere `auto` |
| `S3_BUCKET` | app, worker, Go | `swypik-media` | bucket-ul de media |
| `S3_ACCESS_KEY` / `S3_SECRET_KEY` | app, worker, Go | token R2 | „Object Read & Write”, limitat la bucket |
| `S3_PRESIGN_ENDPOINT` | app | *(gol pe R2)* | endpointul pe care se semnează uploadurile din browser; implicit `S3_ENDPOINT`. Alias vechi `S3_UPLOAD_PUBLIC_ENDPOINT` |
| `MEDIA_PUBLIC_BASE_URL` | app (**runtime + build**), worker, Go, scripturi | `https://media.swypik.com` | originea CDN; baza tuturor URL-urilor publice. Aliasuri vechi: `S3_PUBLIC_URL`, `S3_PUBLIC_BASE_URL`, `R2_PUBLIC_URL` |
| `NEXT_PUBLIC_MEDIA_PUBLIC_BASE_URL` | app (**build**) | `https://media.swypik.com` | loader-ul `next/image` din browser |
| `NEXT_PUBLIC_MEDIA_IMAGE_TRANSFORM` | app (**build**) | `cloudflare` sau gol | redimensionare prin `/cdn-cgi/image/…` pe domeniul media |
| `MEDIA_SIGNING_SECRET` | app + Worker | `openssl rand -base64 48` | cheia token-urilor de media privată (aceeași valoare în ambele) |
| `MEDIA_SIGNED_BASE_URL` | app (**runtime + build**) | *(gol)* | originea URL-urilor semnate; implicit `MEDIA_PUBLIC_BASE_URL` |
| `MEDIA_PRIVATE_PREFIX` | app | `private/` | prefixul fără acces public direct (Worker → 403) |
| `MEDIA_SERVER_PROXY` | app | *(gol)* | doar urgență: `1` repornește proxy-ul de bytes din app în producție |
| `BACKUP_S3_BUCKET`, `BACKUP_S3_ENDPOINT`, `BACKUP_S3_PREFIX`, `BACKUP_RETENTION_DAYS` | cron pe VM | `swypik-db-backups`, … | backup nocturn Postgres (mai jos) |

„Build” = CSP-ul din `next.config.mjs` și loader-ul de imagini se calculează la `next build`; valorile
trebuie date ca build args (vezi `infra/hetzner/docker-compose.prod.yml`; IaC-ul Azure trebuie să le
transmită la fel). CSP-ul strict din `middleware.ts` le citește la runtime.

Video-worker (Python, boto3 ≥ 1.36) și aws-cli v2 recent: setați și
`AWS_REQUEST_CHECKSUM_CALCULATION=when_required` + `AWS_RESPONSE_CHECKSUM_VALIDATION=when_required`
(checksum-urile CRC implicite noi nu sunt acceptate de R2 pe toate operațiile). App-ul setează
echivalentul direct în `lib/storage/s3-client.ts`.

## Configurarea bucket-ului (o singură dată, din dashboard)

1. **R2 → Create bucket** `swypik-media` (locație automată; clasă Standard).
2. **Settings → Custom Domains → Connect Domain** `media.swypik.com` (zona `swypik.com` trebuie să fie
   pe Cloudflare; DNS-ul se creează automat, proxied).
3. **Settings → Public Development URL (r2.dev) → Disable.** În producție doar domeniul custom
   (r2.dev nu are cache, WAF sau Worker-ul de media privată).
4. **Settings → Object lifecycle rules → Add rule**: „Abort incomplete multipart uploads” după **1 zi**
   (sesiunile de upload expiră după 24h, `VIDEO_LIMITS.sessionTtlSec`).
5. **R2 → Manage API tokens → Create**: „Object Read & Write”, *Apply to specific buckets only* →
   `swypik-media`. Cheile → `S3_ACCESS_KEY` / `S3_SECRET_KEY`. Un token separat pentru bucket-ul de backup.
6. **Settings → CORS policy** — JSON-ul de mai jos.

### CORS (bucket-ul de media)

Se aplică atât endpointului S3 (uploadurile presemnate din browser) cât și domeniului custom
(citiri publice cu `fetch`/hls.js). Adăugați orice alt domeniu de frontend (preview, aplicațiile
Capacitor: `capacitor://localhost`, `https://localhost`).

```json
[
  {
    "AllowedOrigins": ["https://swypik.com", "https://www.swypik.com"],
    "AllowedMethods": ["GET", "HEAD", "PUT"],
    "AllowedHeaders": ["content-type", "content-length", "range", "if-none-match", "if-modified-since"],
    "ExposeHeaders": ["ETag", "Content-Length", "Content-Range", "Accept-Ranges"],
    "MaxAgeSeconds": 86400
  }
]
```

Pentru dezvoltare locală pe R2 (rar; local e MinIO) adăugați o regulă separată cu
`"AllowedOrigins": ["http://localhost:3000"]`.

## Upload multipart pe R2 — ce contează

`lib/video/storage-multipart.ts` + `lib/video/limits.ts` respectă deja constrângerile R2:

- **Părți de mărime fixă**: toate părțile au exact `partSizeBytes` (8 MiB) în afară de ultima — R2
  cere părți egale (spre deosebire de S3); minim 5 MiB, maxim 10 000 de părți (max ~78 GiB la 8 MiB,
  mult peste limita de upload).
- **Fără ACL-uri**: nu trimitem `x-amz-acl` (R2 nu suportă ACL-uri per obiect); accesul public e dat de
  domeniul custom, cel privat de Worker.
- **ETag-urile părților** se citesc pe server cu `ListParts` la finalizare, deci browserul nu trebuie să
  citească `ETag` (e totuși expus în CORS).
- URL-urile de `UploadPart` / `PutObject` se semnează pe endpointul S3 R2
  (`<account-id>.r2.cloudflarestorage.com`) — domeniul custom **nu** acceptă semnături SigV4.
- Clientul SDK are `requestChecksumCalculation: "WHEN_REQUIRED"`, altfel SDK-ul v3 ar pune checksum-uri
  CRC în URL-urile presemnate pe care browserul nu le poate respecta.
- CSP: originea endpointului S3 intră automat în `connect-src` (din `S3_PRESIGN_ENDPOINT`/`S3_ENDPOINT`).

## Cache pe CDN (domeniul `media.swypik.com`)

Obiectele se scriu deja cu `Cache-Control` corect: segmente `.ts`, `preview.mp4`, thumbnail-uri,
imagini urcate = `public, max-age=31536000, immutable` (nume unice); playlist-uri `.m3u8` =
`public, max-age=60`. Configurați în zona `swypik.com`:

**Caching → Cache Rules** (în ordinea asta):

1. *Media privată — ocolește cache-ul CDN* (Worker-ul își face singur cache-ul):
   `(http.host eq "media.swypik.com" and (starts_with(http.request.uri.path, "/s/") or starts_with(http.request.uri.path, "/private/")))`
   → **Bypass cache**.
2. *Playlist-uri*: `(http.host eq "media.swypik.com" and ends_with(http.request.uri.path, ".m3u8"))`
   → Eligible for cache, **Edge TTL 60 s** (ignore origin), Browser TTL: respect origin.
3. *Restul media*: `(http.host eq "media.swypik.com")` → Eligible for cache, Edge TTL: **use
   cache-control header if present, else 1 year**, Browser TTL: respect origin. (Fără regula asta R2
   pe domeniu custom cache-uiește doar extensiile implicite ale Cloudflare.)

**Caching → Tiered Cache → Smart Tiered Caching: On** (mai puține citiri Class B din R2).

**Images → Transformations** (opțional): activați pe zona `swypik.com`, permiteți doar originea
`media.swypik.com`, apoi `NEXT_PUBLIC_MEDIA_IMAGE_TRANSFORM=cloudflare` la build.

## Media privată: Worker-ul `infra/cloudflare/media-worker`

URL-urile presemnate R2 **nu funcționează pe domenii custom** (doar pe endpointul S3, fără cache CDN),
iar proxierea video din VM prin CDN nu e permisă de termenii Cloudflare. De aceea media plătită trece
printr-un Worker legat de bucket (binding R2) pe domeniul de media:

- App-ul (`lib/media/signed-media.ts`) emite `https://media.swypik.com/s/<token>/<cale>`; token-ul =
  AES-256-GCM (cheie = SHA-256(`MEDIA_SIGNING_SECRET`)) peste `{prefix, expirare, user}` — criptat, deci
  cheia reală a obiectului (basename-ul aleator al pieselor premium) nu ajunge la client.
- **Episod HLS**: token-ul acoperă *directorul* episodului; `master.m3u8` → `720p/index.m3u8` →
  segmente se rezolvă relativ sub același `/s/<token>/`, fără rescrierea playlist-urilor și fără
  semnarea fiecărui segment. Expirarea = durata episodului + `MOVIES_STREAM_TOKEN_TTL_S`.
- **Piesă premium**: token pe obiect, calea din URL e constantă (`/audio`).
- Worker-ul verifică token-ul, refuză traversarea (`..`, `%2F`), servește din R2 (Range → 206) și
  cache-uiește segmentele la edge sub `/__media/<cheie>` — **fără token în cheia de cache**, deci toți
  cumpărătorii unui episod împart cache-ul. Browserul primește `Cache-Control: private`.
- Acces direct la `/private/...` → 403 (ruta Worker-ului acoperă și prefixul privat).
- Formatul token-ului e testat end-to-end app ↔ Worker în `tests/unit/media-signed-url.test.ts` și
  `tests/unit/media-worker.test.ts`.

Deploy (din `infra/cloudflare/media-worker`):

```bash
npx wrangler login
# editați wrangler.toml dacă diferă: bucket_name, routes (host), ALLOWED_ORIGINS
npx wrangler secret put MEDIA_SIGNING_SECRET      # aceeași valoare ca în .env-ul aplicației
npx wrangler deploy
# verificare: 403 fără token, 403 pe prefixul privat
curl -sI https://media.swypik.com/s/invalid/master.m3u8 | head -1
curl -sI https://media.swypik.com/private/x | head -1
```

Fără Worker (sau dacă e oprit), un **WAF custom rule** trebuie să blocheze
`http.host eq "media.swypik.com" and starts_with(http.request.uri.path, "/private/")`.

În dezvoltare (MinIO, fără Worker, `MEDIA_SIGNING_SECRET` gol) app-ul folosește proxy-ul vechi
`/api/{movies,music}/stream/...`; în producție acesta răspunde 404, iar fără semnare configurată
`/play` întoarce 503 `media_unavailable` (niciodată bytes prin server).

## Cutover (MinIO → R2 nou, fără migrarea fișierelor)

Media existentă e demo și **nu se copiază** (bucket R2 nou, gol). Pași:

1. Bucket + domeniu + CORS + Cache Rules + Worker (secțiunile de mai sus).
2. `.env` producție: variabilele din tabel (runtime **și** build args), apoi rebuild web + restart
   video-worker / platform-api.
3. Migrarea `db/migrations/20260927_0001_archive_demo_media.sql` (aplicată automat de `ops/deploy.sh`
   la primul deploy care o conține — **deci deploy-ul acestui cod = cutover-ul**): ascunde toate
   clipurile, arhivează serialele/albumele/piesele existente și golește URL-urile care indică
   storage-ul vechi (`cdn.swypik.com`, `media.swypik.com`, MinIO, `/media/`), cu backup în
   `data_cleanup_archive` (batch `20260927_0001`, reversare în antetul fișierului). E one-shot: rulată
   din nou nu mai atinge nimic, deci nu poate goli media urcată după cutover.
4. Verificare: upload video nou → procesare → redare în feed; avatar nou; episod plătit (URL `/s/…`).

Nu există unealtă de copiere MinIO → R2 și nici script de rescriere a URL-urilor (decizia ownerului).
Codul nou stochează în continuare atât cheia (`video_assets.object_key`, `music_tracks.object_key`)
cât și URL-ul absolut (`videos.playback_url`, `thumbnail_url`, `users.avatar_url`, …); o schimbare
viitoare a domeniului CDN ar cere rescrierea acestor coloane — de preferat, pe termen lung, derivarea
URL-ului din cheie la citire (`mediaPublicUrl(key)`), cum face deja feed-ul pentru `thumbnail_key`.

## Backup nocturn al bazei de date → R2

`infra/azure/backup-db.sh`: `pg_dump | gzip -9 | aws s3 cp -` direct în R2 (fără fișier local),
verifică mărimea obiectului, apoi șterge backup-urile mai vechi de `BACKUP_RETENTION_DAYS`.

- Bucket separat **privat** `swypik-db-backups` (fără domeniu custom, fără r2.dev) și token separat
  „Object Read & Write” limitat la el. Alternativ `BACKUP_RETENTION_DAYS=0` + lifecycle rule R2
  „Delete objects after N days” pe prefixul `postgres/` (tokenul nu mai are nevoie de ștergere).
- Cerințe pe nodul data: `aws` (aws-cli v2, snap — scriptul adaugă singur `/snap/bin` în PATH),
  `PG_DUMP_CMD="docker exec swypik-postgres pg_dump -U swypik -d swypik_prod"` (sau doar
  `POSTGRES_CONTAINER=swypik-postgres`), `flock`, GNU `date`.
- Env-ul stă în `/opt/swypik/env/backup.env` (600, owner `dev`), încărcat automat de script;
  `LOCK_FILE=/opt/swypik/backup.lock` e comun cu backup-ul pre-deploy (care îl așteaptă).
- Cron (ora 03:15 UTC) al userului `dev` pe nodul data — scriptul vine din release-ul distribuit de deploy:

```cron
15 3 * * * bash /opt/swypik/release/infra/azure/backup-db.sh >> /opt/swypik/logs/db-backup.log 2>&1
```

- Test: `backup-db.sh --dry-run`. Restaurare:
  `aws --endpoint-url "$BACKUP_S3_ENDPOINT" s3 cp s3://swypik-db-backups/postgres/<fișier>.sql.gz - | gunzip | psql "$DATABASE_URL"`.

## Replici web stateless

Pe calea de media/upload nu se scrie nimic pe disc și nu se ține stare în proces: uploadurile de
imagini se validează/redimensionează în memorie (`Buffer`, `sharp`), sesiunile de upload video și
deblocările stau în Postgres, rate-limit-ul în Redis; clienții S3 sunt doar singletoni de conexiune.

## Movies: media plătită în prefixul privat (2026-09-28)

- Episoadele plătite (`episode_number > free_episodes`) stau în `private/movies/<aleator 128 biți>/`;
  directorul NU derivă din id-ul videoului, iar thumbnail-ul e copiat separat la
  `movies/thumbs/<aleator>.jpg`. Worker-ul CDN dă 403 pe `/private/*`; redarea doar prin `/s/<token>/…`.
- Importul admin (`mediaUrl`) al unui episod plătit transcodează direct în directorul privat
  (`lib/movies/private-ingest.ts`). Un video existent atașat ca episod plătit, sau un episod devenit
  plătit (free_episodes micșorat), e mutat imediat (`lib/movies/private-media.ts`: copiere → DB → ștergere copii publice).
- Plase de siguranță: ruta `play` mută inline sau refuză (409) un episod plătit încă public; cron-ul
  `daily-maintenance` (job `movies-license-expiry`) trece prin toate episoadele plătite rămase publice.
- **Migrarea one-shot a episoadelor existente** (idempotentă, înlocuiește `scripts/data/privatize-paid-episodes.mjs`),
  ca admin, după pornirea `FEATURE_MOVIES`:
  1. `POST /api/admin/movies/privatize-media` cu `{}` → dry-run, întoarce `checked`;
  2. `POST … {"dryRun": false, "limit": 200}` → repetă până `checked` = 0 (`failed` > 0 → vezi logurile `[movies]`).
- Un re-encode admin (`/api/admin/videos/[id]/reencode`) rescrie în `videos/hls/<id>/`; trecerea zilnică îl mută la loc.

## Rămas de făcut

- Uploadurile de imagini prin formular (avatar, poze produs, atașamente DM, dovezi retur) trec încă
  prin app (≤5 MB, validare + `sharp`). Pentru zero bytes prin VM: upload presemnat direct + validare
  asincronă (worker) — schimbare separată.
- Piesele premium stau sub `music/raw/…` (public, protejate doar de basename-ul aleator, care nu mai
  ajunge la client); mutarea lor sub `private/` la marcarea ca premium ar închide complet accesul direct.
