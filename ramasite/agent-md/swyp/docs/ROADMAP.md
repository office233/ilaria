# Swyp roadmap

Distilled from [the 2026-09-28 research campaign](../history/AI_LANGUAGE_RESEARCH_20260928.md).
Correctness is mandatory; speed, size and ergonomics are compared only among
correct variants.

## Done

- **Native runtime parity (2026-10-02).** `cmd/swyp/native_runtime_parity_test.go` runs one corpus (Core scalars/argv/IO/fs/net/clock/rng, 38 HIR storage/vec/struct/slice/ref programs and Core-interpreter differential cases for checked arithmetic, loops, spills and calls) on every executable target the host can really run: Windows x86-64 PE, Linux x86-64 static ELF and PIE, and Linux AArch64 static ELF and PIE natively or under `qemu-aarch64` user-mode emulation via `SWYP_QEMU_AARCH64` (CI installs `qemu-user` on Ubuntu). It found and fixed: an x86-64 SSE two-address miscompile when the destination register aliased the right operand (`a-b`→0, `a/b`→1, `a+b`→2a, `a*b`→a²; direct machine code and the text-assembly backend); missing integer `div`/`rem` in both direct machine backends (now checked: zero divisor and `MIN/-1` trap, `MIN%-1` is 0); AArch64 non-leaf functions that never saved `x30`, so every function calling a runtime helper or another function crashed on return; an inverted AArch64 IPv4 terminator check that rejected every valid literal for `net.connect`/`net.fetch`; and an AArch64 `i64` multiply overflow check that could read a clobbered operand. AArch64 runtime evidence is qemu-user, not physical hardware.
- Scalar language with interpreter, C and JS backends.
- STV2 VM and SWYPB modules for a safe-integer subset (fuzzed, differential-tested).
- **M1a** Semantic Core: typed `i64`/`f64`, JSON IR, verifier, fuel-bounded executor.
- **M1b (partial)** Contracts with `exhaustive`/`tested`/`counterexample`/`unknown`/`timeout`
  and contract-guided synthesis.
- Declarative platform components plus deterministic JSON/Go code generation for Ilaria and SwypikOS contracts.
- Semantic Core native AOT with `safe`/`fast` profiles and explicit `ieee64` compute semantics.
- Allocation-free hot path for common prepared Core programs: small frames + unary/binary operations can run with zero heap allocations; `RunFast` adds coarse bounded execution for embedded latency-sensitive use.
- Compact typed Turbo bytecode with cold side tables and compact terminators for persistent sub-millisecond embedded execution.
- SSA, phi-aware liveness, deterministic register allocation and GPR/FP stack spilling for direct x86-64 and ARM64 CFG backends.
- Bounded pure-function inlining plus acyclic scalar native calls; recursive call cycles fail closed.
- Packed x86-64 machine-code artifacts now cover leaf functions, GPR CFGs with branches/loops/phi/spills, closed acyclic scalar call graphs with internal `rel32` relocation, explicit `ieee64` CFGs with FP spills, and mixed GPR/FP native calls with Win64 positional ABI and nested status propagation.
- Packed ARM64 machine-code artifacts now cover GPR/`ieee64` CFGs, GPR/FP spills and phi copies, and closed acyclic mixed GPR/FP call graphs with internal `BL` relocation and call-safe status propagation, with `.swa64` hash-verified modules.
- Direct ARM64 object emission now produces deterministic ELF64/AArch64, Windows ARM64 COFF and Darwin ARM64 Mach-O relocatable objects from Swyp-generated machine code without an external assembler.
- Direct x86-64 object emission now produces deterministic Windows AMD64 COFF, ELF64/x86-64 and Darwin x86-64 Mach-O relocatable objects; ELF/Mach-O entries use an explicit SysV-to-Win64 ABI thunk while internal Swyp code stays unchanged.
- Direct Windows x86-64 link-image emission now produces loadable PE32+ DLLs with exported Swyp entry functions and no external assembler/linker; integer and mixed-FP exports are runtime-tested through `LoadLibrary`/`GetProcAddress`.
- PE32+ DLLs now carry a real base-relocation table plus `DYNAMIC_BASE`/`HIGH_ENTROPY_VA`; dual-copy runtime tests force relocation at a non-preferred base.
- Direct standalone Windows x86-64 executables now emit PE32+ images without an external linker and parse up to four typed `i64/u64/bool/ieee64` argv values without a CRT; runtime tests cover boundaries, malformed input and FP exponent syntax.
- Direct standalone Linux x86-64 executables now emit static ELF64 `ET_EXEC` images with no libc/dynamic loader/imports, terminating through the Linux `exit` syscall.
- The x86-64 SysV-to-Win64 entry adapter is now runtime-tested via GCC `sysv_abi`, including mixed FP and four-GPR argument mappings.
- Direct x86-64 executables now parse up to four `i64/u64/bool/ieee64` command-line parameters without a CRT; Windows runtime tests cover full integer boundaries, bool tokens, decimal/exponent FP parsing, quoted executable paths and fail-closed invalid argv.
- Direct standalone Linux ARM64 executables now emit static ELF64/AArch64 `ET_EXEC` images with no dynamic loader/imports, parse mixed AAPCS64 typed argv across independent GPR/FP banks, and use a syscall-only `exit(93)` wrapper; structural/opcode tests and `linux/arm64` cross-builds pass.
- Direct native `bytes.get` now resolves checked immutable module-arena descriptors on x86-64/AArch64 and checked mutable runtime-arena descriptors produced by `fs.read`. `fs.read` is runtime-complete on x86-64 and structurally complete on Linux AArch64 with a bounded RW/non-executable arena; real ARM64 execution remains the validation gap.
- Native process RNG is now first-class: `random()` lowers to capability-tagged `rng.sample`, uses Windows `BCryptGenRandom` or Linux `getrandom` syscalls, is runtime-tested on Windows x86-64, structurally tested on ARM64, and remains fail-closed in reusable pure packed artifacts.
- Static PIE emission now exists for both Linux x86-64 and AArch64 as zero-based ELF64 `ET_DYN` images with PC-relative control flow and no dynamic relocation table; structural validation passes, while runtime ASLR validation awaits a Linux/ARM64-capable execution environment.
- Core process IO is now explicit and capability-gated: `print`/`eprint` lower to `io.stdout`/`io.stderr`, effect metadata propagates through calls, reusable artifacts remain pure-only, and standalone x86-64 runtime tests verify separated stdout/stderr. Linux x86-64/AArch64 use direct write syscalls; IEEE64 output now uses one exact canonical hex-float formatter across architectures without a CRT.
- Core `clock()` now lowers to capability-gated `clock.read -> u64`; standalone Windows/Linux x86-64 execute monotonic clock reads without a CRT, and Linux AArch64 lowers to the native `clock_gettime` syscall path.
- Core `write_file(bytes,bytes)` now lowers to capability-gated `fs.write`; standalone builds require explicit `-allow-fs-write`. Windows x86-64 writes are runtime-tested, Linux x86-64 uses direct `openat/write/close`, and Linux AArch64 uses syscalls 56/64/57 with a PC-relative module byte arena.
- Direct native `bytes.len`/`bytes.get` now work on x86-64 and AArch64 with checked descriptor bounds across immutable module bytes and the committed prefix of the mutable `fs.read` arena. Module bytes live in dedicated read-only/non-executable `.rdata` (PE) or `.rodata` + `PF_R` (ELF) regions; dynamic read data lives in a separate bounded RW/non-executable runtime segment. Linux AArch64 `fs.read` lowers to `openat/lseek/read/close` syscalls and preserves monotonic arena allocation.
- Capability-gated `tcp_connect(bytes,u64)->bool` now lowers to `net.connect`: IPv4-literal only, explicit `network_connect` grant, no DNS/HTTP. Windows x86-64 is runtime-tested on loopback with Winsock; Linux x86-64 uses syscalls 41/42/3; Linux AArch64 uses syscalls 198/203/57 with structural/cross-build validation.
- Capability-gated `http_fetch(bytes,u64,bytes)->bytes` now lowers to `net.fetch` with an independent `network_fetch` grant. The v1 contract is deliberately narrow: plaintext HTTP/1.1 only, IPv4 literals only, visible-ASCII absolute paths, no DNS, no TLS and no redirect following. Responses are returned as raw bounded bytes in the mutable process arena; connect/send/receive are timeout-bounded, overflow fails closed, and socket/runtime-arena cleanup is explicit on failure. Windows x86-64 is loopback runtime-tested; Linux x86-64 and Linux AArch64 have direct syscall implementations, with AArch64 still requiring real-hardware/QEMU runtime validation.
- `process.exec` now has a source/Core semantic contract and a dedicated `process_exec` capability. `process_exec(executable, argc, argv0, argv1, argv2, argv3)->u64` uses explicit argv slots rather than a shell command string. Standalone x86-64/AArch64 builds require `-allow-process-exec`, but both native backends intentionally fail closed after the grant because the OS runtime, executable allowlist, timeout/termination and output policy are not implemented yet.
- **M0 compiler truth is closed:** one compiler-owned language version drives `version`, AI generation provenance and `language-manifest`; draft/repair prompts derive from the current compiler surface; Ilaria endpoint/token selection is configurable; source parser/checker diagnostics now expose stable versioned codes and source locations, and model-facing JSON commands preserve them without requiring message-text matching.

## Next

1. **M1 Unified HIR / ownership boundary.** The common `module`/`use` preamble, deterministic graph, typed bodies and qualified `hir-link` are connected end-to-end to Core/native backends. HIR covers nominal values, exhaustive enums, option/result, arrays/indexing and slice views. `swyp-fixed-v1` plans fixed layouts; `swyp-descriptor-v1` defines logical slice/vec/ref/mutref descriptors and overflow-safe index/range invariants without raw pointers; `hir-bounds` emits deterministic `proven` vs `runtime_required` evidence and rejects static OOB. Affine checking tracks Copy/Move/Borrowed plus explicit `drop`; lexical `&`/`&mut` loans enforce shared/exclusive scope rules with Copy-only dereference/store. Explicit `borrows <param>` contracts validate borrowed-return provenance locally and across linked calls. Static fields, distinct constant indices and disjoint constant ranges participate in place analysis. Core interpreter profiles and standalone x64/ARM64 share a bounded opaque storage contract. Large arrays/slices and raw64 vec owners use it; vec params/returns cross explicit descriptor ABIs, flat structs support Copy/ref/slices, and nested by-value structs whose leaves are raw64 flatten recursively for constructor/push/Copy/leaf projection/ref through vec/slice descriptors. Canonical bool words (`0`/`1`, rejecting other decode values) now use these same storage paths, including `vec<bool>`, large bool arrays and mixed flat/nested struct leaves, without changing the logical one-byte bool layout or adding a backend. Differential tests cover Windows x64 and Linux x64/AArch64 QEMU static/PIE, OOB and invalid bool words. `defer_drop(v)` provides deterministic LIFO cleanup for local vec owners and top-level moved vec parameters. Packed modules stay stateless. Next generalize aggregate assignment/parameter/result and destructor contracts, and add other non-raw64 storage leaves.
2. **Closed loop with Ilaria (Nexus).** Register a Swyp `ChatTool` so the model
   can propose a program plus contract and receive a verification report or a
   counterexample to repair. Verified pairs feed Nexus fine-tuning data.
3. **SwypikOS tool.** An approval-gated `swyp.verify` / `swyp.exec` agent tool
   running SWYPB modules on the STV2 VM.
4. **Semantic Core as the single front end.** Core IR -> native C AOT, compact Turbo execution and direct native lowering exist; retire the legacy float-only compiler path only after feature parity.
5. **M2 – ownership, memory and optimizer.** The existing opaque Core `bytes` descriptor ABI remains bounded and capability-safe. HIR separately defines `swyp-descriptor-v1`, deterministic bounds evidence, affine moves, lexical loans and lifetime contracts. Bounded storage is shared by interpreter/Fast/Turbo and standalone x64/ARM64; vec owners/views, recursive raw64 struct strides, leaf refs, vec parameter/return descriptors and read-only struct slices use it without raw pointers. Explicit `defer_drop` covers local vecs and top-level moved vec parameters. x64 is runtime-tested on Windows and ARM64 is structurally/cross-build validated. Next generalize destructor contracts to additional runtime owners, materialize nested aggregates locally, add non-raw64 layouts and extend range/refinement analysis; only `proven` evidence may remove bounds checks.
6. **Direct native backend.** Linux x86-64 and AArch64 (qemu-user) runtime parity now covers argv, PIE, process IO, `fs.read`/`fs.write`, `net.connect`, `net.fetch`, clock, rng, storage and native calls; physical AArch64 hardware and Linux ASLR behavior under real kernels remain to be measured. Complete the already capability-gated `process.exec` runtime with exact executable allowlisting, no shell, bounded lifetime/termination and an explicit output policy. Future richer network IO must remain separately capability-gated rather than widening `net.fetch`; keep C AOT as a differential reference backend.
7. **M3 – richer synthesis.** Comparisons and conditionals in the grammar,
   symbolic verification on a subset, held-out evaluation.
8. **Effects and capabilities.** Pure functions separated from filesystem,
   network, clock and model effects; generated code gets only declared
   capabilities.
9. **M4 – tensors and apps.** Shape/dtype-explicit tensor ops through an
   established backend; modules/packages; C/Python interop.

## Rules for claims

- `tested` is sampling, `exhaustive` is finite-domain execution; neither is an
  SMT proof.
- A delegated agent's "done" is not evidence; only reproduced commands, exit
  codes and hashes are.
